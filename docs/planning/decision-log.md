# Voysemble decision log

Working branch: `next`. Direct commits while scaffolding. No PR cycle.

Standing rule: document everywhere. See docs/engineering/documentation-rules.md.

Status legend: `open` (being grilled), `decided`, `deferred`.

Scenario interviews (2026-10-11) produced D12-D29; ADR-0009 holds the full rule set and visibility matrix.

| # | Topic | Status | Decision | Why |
|---|---|---|---|---|
| D01 | Product boundary | decided | Single-operator platform (founder only), org-scoped data. Build docs 01-03 product. Doc 00 = security posture source. Encryption in tiers: ops data plaintext in D1; PII fields AES-256-GCM with per-org DEK wrapped by Worker-secret master key; documents in R2 ciphertext with seam for owner-held key later; live coords ephemeral in DO only. Stripe web-only, organizers only, hosted Checkout + Portal, no card data. Admin = Cloudflare Access + single staff identity + audit + reauth. | Server needs ops plaintext for role filtering, sync, fanout, graph. Full E2E kills those. PII/doc encryption still defeats DB/backup leak. |
| D02 | Mobile client runtime | decided | Kotlin Multiplatform core (API client, sync, offline SQLite, crypto, domain rules) + SwiftUI + Jetpack Compose. No JS runtime in app. ADR-0003. | Minimal supply chain, OS-level background reliability, native look. Sync/crypto written once. |
| D03 | AI boundary | decided | Workers AI via AI Gateway for organizer-side tasks (ingest suggestions, broadcast translation, image moderation flags, proposal explanation). Mobile uses platform-native on-device ML (Apple Translation/Vision/Speech/Foundation Models; ML Kit/Gemini Nano). `AiPort` with on-device/remote/disabled impls. No bundled LLM weights. ADR-0006. | Zero-cost, offline, private on mobile. Low-volume paid inference only where organizers benefit. |
| D04 | Auth, sessions, email | decided | `arctic` + `@oslojs/*` primitives, own session/device/invite tables. Apple/Google OIDC web (PKCE), native sign-in on mobile, magic link fallback, sealed role links for guests, Access for admin. Opaque hashed sessions, rotating refresh. Email via Cloudflare Email Sending behind `EmailPort`. ADR-0007. | Smallest surface, custom membership model, no identity vendor. |
| D05 | Build order | decided | P0 scaffold -> P1 visual foundation (PC command center, PC itinerary, mobile Today, mobile radius) -> P2 identity+trip -> P3 realtime+offline -> P4 media -> P5 Journey Graph -> P6 Stripe -> P7 admin -> P8 pilot. Web console first in P1. `planning/prototype-work-graph.json`. | Stripe fixture-only until keys; web screenshots verifiable in Linux CI. |
| D06 | Storage topology | decided | Global D1 (identity, org directory, billing, staff audit, rollups) + OrgDO SQLite canonical per org + TripLiveDO per trip (sockets, presence, coords, chat stream) + R2 longitudinal archive + KV config. Drizzle ORM. No PlanetScale. ADR-0002. | Isolation by construction, real transactions, co-located compute, $0.20/GB-mo, zero ops. Cross-org via rollups. |
| D07 | API style | decided | OpenAPI-first REST via Hono + zod-openapi; generated Kotlin/Swift/TS clients. No GraphQL. ADR-0004. | Role-scoped endpoints, native codegen, no resolver N+1 on DO, less attack surface. |
| D08 | Key hierarchy, rotation, PQ | decided | KEK (Worker secret) wraps per-org versioned DEKs; envelope with keyVersion; lazy + async re-encrypt; crypto-shred on org delete. Symmetric-only at rest, HMAC tokens, hybrid X25519+ML-KEM when asymmetric needed. ADR-0005. | Rotation without mass rewrite; PQ-ready by construction. |
| D10 | Environments and hostnames | decided | Prod `voysemble.com` (`app.`, `api.`, `admin.`, `assets.`). Preview `<build>.dev.voysemble.cfd` with `api.`, `admin.`, `www.` prefixes. Staging `staging.dev.voysemble.cfd`. (Suffix changed from `dev.vida.re` on 2026-10-10.) Per-build D1/DO/R2/KV. App + API same origin; admin separate Worker. ADR-0008. | Host-only cookies, no CORS for web, isolated previews, auto certs via Custom Domains. |
| D11 | Languages | decided | KO and EN only. EN source strings. Locale-agnostic i18n so JA can be added later. | Founder decision. |
| D12 | Onboarding and invites | decided | Organizer imports roster CSV (name, group, guardian contact). Each roster row gets a per-person invite code; guardian codes are bound to one traveler. Role comes from the invite, never from self-selection. ADR-0009. | Roster is the source of truth; codes bound to rows stop strangers and role drift. |
| D13 | Guardian visibility | decided | Guardians see status, not coordinates: head-count result for their traveler, published itinerary, announcements marked "share with guardians", approved photos tagged with their traveler or whole group. No live map, no room numbers, no sync timestamps. ADR-0009. | Reassurance without surveillance; avoids false alarms from raw telemetry. |
| D14 | Offline head count | decided | Local-first on leader device. Idempotency key per head count, device time recorded, can close offline, shows explicit "Pending sync" until server ack. Sync once, conflict-free by construction (one leader per group per head count). ADR-0009. | Buses and mountains have no signal; the count must still close. |
| D15 | Location sharing | decided | No ambient tracking. Leader opens a meeting window (time range + zone radius); traveler opts in per window; states inside/outside/uncertain/stale; auto-stop at window end; guardians never see it. ADR-0009. | Minimal data, explicit consent, bounded lifetime. |
| D16 | Announcements and acks | decided | Announcement has required-ack flag. Traveler taps "Got it" (queued offline). Leader sees unacked list live, can schedule a nudge push and hand list to room check. KO<->EN machine translation via Workers AI, original always shown, translation labelled "machine". Guardians receive only if marked "share with guardians". ADR-0009. | Read receipts lie on sleeping phones; explicit ack plus escalation list is what leaders act on. |
| D17 | Incident and person timeline | decided | Console has per-person timeline (syncs, head counts, acks, leader-tagged photos, notes). Organizer opens incident card, pings leader to confirm. Leader confirms from mobile. System sends guardian a status message in their language naming the confirming leader and time. Photos only if organizer attaches. All steps audited. ADR-0009. | Evidence trail plus human confirmation; guardian gets a verified answer, not raw data. |
| D18 | Photos and moderation | decided | Uploads go to trip pool (travelers + leaders). Workers AI image moderation flags nudity and close-ups of non-member minors; flagged photos hidden pending leader review. Leader approves per photo for guardian album. EXIF location stripped on upload. Originals ciphertext in R2. Uploader can delete own photo everywhere. ADR-0009. | Keeps leaders in control without making the organizer a bottleneck. |
| D19 | Disruption replanning | decided | Organizer triggers "Disruption" on a day. Workers AI drafts 2-3 proposal variants with explanation. Organizer edits in itinerary editor and publishes a new revision. Everyone gets a diff view with required ack. Guardians get parent-safe summary. Old revisions kept. ADR-0009. | AI accelerates; organizer stays single publisher. |
| D20 | Retention and deletion | decided | Trip close starts 90-day wrap-up window. Then per-trip PII key is crypto-shredded: names, contacts, photos, chat unreadable. Itinerary template, head-count stats, anonymized timing kept. Per-person deletion request shreds that person's row key immediately; audit entry remains. Org default configurable 30-365 days. ADR-0009, ADR-0005. | PIPA/GDPR friendly, keeps templates and multi-year insight. |
| D21 | Accounts, orgs, roles | decided | One global account (D1). Membership = account x org with org role (owner, organizer, leader, member). Trip participation = membership x trip with trip role (leader, traveler, guardian-of-X). Org switcher in apps. Invite code joins org and trip in one step. Account sees only orgs it joined; each org's data under its own DEK. ADR-0009. | Leaders work for several orgs; travelers return years later. |
| D22 | Chat channels | decided | Fixed channels only: trip-all, per-group (leader-moderated), traveler->leader 1:1, guardian->organizer 1:1. No traveler<->traveler DM, no guardian<->leader DM. Organizer can open any channel on incident with audit entry. ADR-0009. | Minors and liability; leaders kept out of parent threads. |
| D23 | Payments scope | decided | Stripe bills the organizer only (per-trip or seat plan, web only). Traveler fees are a ledger: paid/unpaid/refunded per roster row, manual or CSV. Guardians see own balance and due date on mobile, no card entry. Optional Stripe Checkout link per traveler later, still web-only. No Stripe Connect. ADR-0009, ADR-0001. | Single-operator friendly; no money-transmitter scope. |
| D24 | Offline itinerary edits | decided | Mobile itinerary is read-only published revision. Leaders file change proposals (queued offline). Organizer accepts/rejects in editor. Single writer per trip: organizer web. Announcements can still be queued offline by leaders. ADR-0009. | No merge conflicts; matches D19 single publisher. |
| D25 | Missing travelers at head count | decided | Missing list pinned top with name, room, last ack, last window status. One-tap call, push "come to Bus A now", mark "with other group" or "excused". Unresolved at close: head count closes with named missing, dashboard tile amber, incident card auto-created. No auto-locate (D15). ADR-0009. | Leader has five minutes; actions must be one tap. |
| D26 | First-run onboarding | decided | Create org (name, KO/EN) -> create trip from template (sample 13-day or blank) -> import roster CSV -> generate invite codes, export PDF/CSV. Dashboard shows checklist until done; sample trip offered so console never looks empty. ADR-0009. | Ten minutes to something useful. |
| D27 | Care notes and documents | decided | Care note (allergy, medication, short text) = PII tier; decrypted for leaders of that traveler's group, shown on head count and person card behind an eye icon; each reveal audited. Passport/consent scans = document tier, organizer web only, reveal needs reauth, watermarked view, never on mobile. Third parties (driver, hotel) get time-limited sealed link or print. Guardian enters/edits care note during invite flow. ADR-0009. | Allergy must be one tap at lunch; scans must not live on ten phones. |
| D28 | Lost or stolen device | decided | Organizer "Revoke devices" on person card (reauth). All sessions killed; next sync from the device gets 401 plus wipe directive. Local cache encrypted with device-keystore key; cached PII 24h TTL, cleared on background lock; chat cache 7 days. Re-enrol by invite code on new phone, groups restored. ADR-0009. | Volunteers use personal phones; no MDM. |
| D29 | Notification rules | decided | Guardians: daily digest at org-set local hour plus immediate only for incident status and share-with-guardians announcements. Travelers: required-ack announcements and head-count calls are priority (high-importance channel, bypass mute); rest normal and mutable. Leaders: all immediate. Per-trip quiet hours (default 23:00-06:30) except priority. ADR-0009. | Fourteen pushes on day one makes guardians uninstall; muting must not hide the bus call. |
| D09 | Source headers | decided | Every source file starts with `Copyright 2026- At Day. All rights reserved.` CI header lint. See docs/engineering/source-headers.md. | Founder requirement. |
